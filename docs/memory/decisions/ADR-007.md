# ADR-007: Firmware fora do workspace, um projeto por placa

- **Status:** aceita
- **Decidido por:** os dois autores, em conjunto
- **Regras afetadas:** —

## Contexto

Cada placa exige toolchain e alvo próprios. Se o firmware fizesse parte do workspace, `cargo test` na raiz tentaria compilá-lo para o host.

## Decisão

O workspace de host contém a biblioteca e ferramentas auxiliares, como `tools/console/`. O firmware permanece isolado em `firmware/`, com um projeto por placa, `publish = false` e dependência da crate por caminho.

## Justificativa

Mantém os comandos da raiz rodando sem hardware e o caso de uso fora do que vai para o crates.io.

## Consequências

O núcleo e as ferramentas de host são testados sem depender do ESP32. O firmware possui configuração e build próprios e deve ser compilado e gravado explicitamente com a toolchain ESP.
